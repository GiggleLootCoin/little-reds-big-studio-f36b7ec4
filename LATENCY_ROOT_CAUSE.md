Root cause identified: BuddyLiveChat already passes model_size 0.6B for cloned live speech, but studio-runtime routes that request through createBestFreeVoiceClone(), which hard-codes Qwen3-TTS 1.7B. Therefore live Buddy speech pays the slower 1.7B generation cost. The fast fix is to pass the requested model size through the runtime/gateway while retaining 1.7B for explicit high-quality cloning.
